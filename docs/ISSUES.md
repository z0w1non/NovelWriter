# ISSUES.md

## 既知の課題

- SillyTavern のデータ配置はバージョンやユーザー設定で異なる可能性があるため、`sillytavern_root`、`sillytavern_user`、ファイル名を確認する必要がある。
- 現在の実装は JSON キャラクターカードを対象とする。PNG キャラクターカードしかない場合は JSON に変換して配置する必要がある。
- KoboldCpp の生成 API の応答形式やパラメータ名がバージョンにより異なる場合は、`generate_path` と応答抽出処理を調整する必要がある。
- `generate_path` は KoboldCpp のバージョンや API 設定によって異なる可能性がある。
- SillyTavern の HTTP サーバー、Cookie、CSRF には依存しない。

- SillyTavern やブリッジのバージョンによって生成パラメータ名や応答形式が異なる可能性がある。
- 長い小説では、既存本文の末尾 `MaxContextCharacters` 文字だけを文脈として送るため、冒頭の設定を参照できない。
- 校正者が本文以外の説明を返す場合、そのまま成果物へ混入する可能性がある。
- 途中で API が切断された場合のリトライやチェックポイントは未実装。
- 同時実行時のファイルロック制御は未実装。
- 構成の章数と実際の進行章番号が一致するかは自動検証していない。
- 構成執筆者が返す JSON の章番号が欠落・重複している場合の詳細な検証は未実装。

## 今後の候補

- 章単位のメタデータと要約を保存する。
- API 応答形式を検証するテスト用モックを追加する。
- リトライ、タイムアウト、ログ出力を設定可能にする。
- 生成本文と校正本文を別ファイルへ保存し、差分確認を可能にする。
